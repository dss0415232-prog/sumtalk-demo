숲톡 민원AI

묻기만 하세요. 연결과 안내는 AI가 합니다.

국립산림치유원 시범 적용 · 하나의 AI 민원 플랫폼 + 기관별 데이터

문제와 해결 — “담당자 찾기”에서 “묻기만 하면 연결”로

지금

  • 국민: 어느 부서인지 모름 · 부재중 재전화 · 부서 간 핑퐁
  • 직원: 반복 질문 누적 · 단체예약 전화 상담 반복 · 연락처 노출
  • 예상 밖 질문(예: 객실 전망)은 답이 쌓이지 않고 매번 새로 응대

숲톡 민원AI

  • 하나의 대화창에서 AI가 근거자료로 먼저 답변
  • 모르면 추측 없이 담당 업무로 구조화해 전달(다시 묻지 않음)
  • AI는 직원을 대체하지 않고 반복 설명을 줄임

만든 이유 — 예상 밖 질문을 자산으로

현실

  • 고객 질문은 예상 밖이 많음 (예: “어느 객실이 뷰가 좋은가요?”)
  • 고객 입장에서는 궁금한 것이 다양하고, 답은 전화·게시판에서 한 번 쓰이고 사라짐
  • 같은 질문이 반복되어 직원 응대시간이 계속 소모됨

숲톡의 질문 축적 순환

  • ① AI가 답하지 못한 질문 자동 수집(개인정보 가림)·유사 질문 묶기·빈도순
  • ② 직원이 답변을 한 번 작성
  • ③ 고객지원팀 담당자가 승인
  • ④ 승인 즉시 다음 고객부터 AI가 1차 응답

직원: 반복 응대 감소 · 고객: 질문이 쌓일수록 더 많은 질문에 바로 답을 받는 새로운 경험 · 기관: 실제 질문 데이터로 서비스 개선 · 승인된 지식만 사용하므로 오답 위험 통제(모델을 재학습하지 않고 지식 데이터가 늘어나는 방식) · 관리자 화면 「질문 축적」「FAQ 승인」

핵심 기술 4가지 — LLM + RAG + 민원 분류 + 담당 자동 라우팅

LLM
질문 의도 이해
근거 안에서만 문장 생성
RAG
5개년 민원 분석·공식자료·규정·FAQ에서 근거 검색
민원 분류
유형·담당 업무 판정
자동 라우팅
담당 업무로 전달·직원 보호 표시

근거 없으면 답하지 않고 담당자 연결 · 숫자가 근거에 없으면 LLM 답변 폐기 · LLM 장애 시 검색 기반 답변으로 자동 대체

시연 — 3가지 장면 LIVE

① 단순 질문

  • “방값이 어떻게 되나요?”
  • 근거·기준일 표시, 담당자 연결 없이 종료

② 담당자 상담

  • 분류 → 희망 연락방법·시간
  • 담당자 화면에 내용·AI 사전답변·확인사항 전달

③ 단체예약

  • 질문 → 예시 일정표 → 예상 견적 → 이메일·상담 요청
  • 예약 가능 여부는 확정하지 않음

▶ 국민용 화면 · ▶ 관리자 화면

모델 비종속 구조 — 어떤 LLM이든 같은 자료, 같은 결과

교체 가능

  • ChatGPT(OpenAI) · Claude · OpenAI 호환(Gemini·국내 LLM 게이트웨이)
  • 환경변수 3개로 전환 · 코드 수정 없음
  • 데이터(FAQ·규정·요금)는 LLM과 분리

안전장치

  • 근거 번호 [근거n] 밖의 내용은 사용 금지
  • 숫자·요금 검증 · 형식 검증 실패 시 대체 경로
  • LLM 없이도 전체 시나리오 동작

직원 보호 · 개인정보

  • 국민 화면에는 담당 업무만 표시 — 담당자 개인 연락처 비공개
  • 폭언·위협 표현은 차단하지 않고 안내 + 내부 표시, 반복 문의는 이력 연결
  • 국민용/관리자용 권한 분리 · 연락처 마스킹 · 요청 횟수 제한
  • 해커톤 데이터는 공개자료·모의데이터만 사용 · 실제 개인정보 미사용

효과 측정 — KPI와 정확도 점검 시범 적용 시 실측

KPI(관리자 화면 집계)

  • AI 1차 응답으로 담당자 연결 없이 해결된 비율
  • 담당자 전환율 · 반복문의 · 단체상담시간

정확도 점검 도구

  • 정답률 · 오답 확신률 · 범위 밖 질문 과신율
  • 시험 질문 43개(작성자 작성)로 점검 — 실제 문의로 재평가 필요

시연 화면의 수치는 모의 로그이며 실제 성과가 아닙니다.

확산 — 하나의 플랫폼, 기관별 데이터만 교체

교체하는 것(data/ 폴더)

  • CSV 7종(FAQ·요금·프로그램·식사·대관·단체규칙·담당업무) 작성 → 변환 명령 1회
  • 1:1 문의·규정은 검수 후 승인분만 반영
  • 기관 사진·LLM 연결만 설정

확장 시나리오

국립산림치유원 → 진흥원 → 산림청 산하기관 → 타 공공기관 → 중앙행정기관
궁극: 어느 기관인지 몰라도 하나의 질문창에서 기관→부서→답변까지 안내

별도 설치 없이 Python 하나로 실행 · 정보화사업 이관 시 DB·인증·메일만 교체

한계와 다음 단계

  • 요금·규정은 모의/공개자료 기준 → 기관 확정 자료로 교체 필요
  • LLM 연동은 제출 환경에서 실제 키로 시험 필요, SMTP·문자 발송은 기관 시스템 연동 단계
  • 정확도는 작성자 시험 질문 기준 → 실제 문의 이력(비식별)으로 재평가 필요
  • VoC는 설문 의견이라 집계 분석에만 사용(질문-답변 학습 데이터 아님)
